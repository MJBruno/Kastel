# Kastel

> **Kastel** est un langage de programmation dynamique, inspiré de JavaScript et Python, conçu pour être interprété par une machine virtuelle à bytecode.

Kastel vise à proposer une syntaxe moderne et expressive tout en reposant sur une architecture interne claire : **lexer → parser → AST → compilateur → bytecode → machine virtuelle**.

Le projet est également conçu comme une implémentation complète de langage, permettant d'expérimenter avec la compilation, les machines virtuelles, les environnements d'exécution et la gestion des valeurs dynamiques.

---

# Architecture

Kastel repose sur une architecture en plusieurs couches.

```text
                 ┌──────────────────┐
                 │   Code source    │
                 │     Kastel       │
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │      Lexer       │
                 │     Tokens       │
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │      Parser      │
                 │       AST        │
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │    Compilateur   │
                 │     Bytecode     │
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │  Machine Virt.   │
                 │       VM         │
                 └────────┬─────────┘
                          │
                          ▼
                 ┌──────────────────┐
                 │    Exécution     │
                 └──────────────────┘
```

Chaque composant possède une responsabilité précise.

### Lexer

Le lexer analyse le code source et le transforme en une séquence de tokens.

```text
let answer = 42;
```

devient conceptuellement :

```text
LET
IDENTIFIER("answer")
EQUAL
INTEGER(42)
SEMICOLON
```

### Parser

Le parser transforme les tokens en structure syntaxique exploitable par le compilateur.

Il prend notamment en charge :

* expressions ;
* déclarations ;
* fonctions ;
* appels de fonctions ;
* structures de contrôle ;
* tableaux ;
* accès aux membres ;
* modules ;
* `return` ;
* `export` ;
* etc.

### Compilateur

Le compilateur transforme l'AST en **bytecode Kastel**.

Il est responsable notamment de :

* générer les instructions ;
* gérer les variables locales ;
* gérer les variables globales ;
* compiler les fonctions ;
* compiler les expressions ;
* gérer les appels ;
* produire les constantes ;
* gérer les structures de contrôle ;
* résoudre les références nécessaires à l'exécution.

### Machine virtuelle

La VM exécute le bytecode produit par le compilateur.

Elle constitue le cœur du runtime de Kastel.

# Syntaxe

Kastel adopte une syntaxe volontairement proche de JavaScript et Python, tout en conservant ses propres règles.

## Variables

```kastel
let name = "Kastel";
let version = 1;
let enabled = true;
```

Les variables utilisent un typage dynamique.

Une même variable peut recevoir différentes valeurs au cours de son existence :

```kastel
let value = 42;

value = "hello";
value = true;
```

## Constantes

Kastel permet également de déclarer des valeurs constantes :

```kastel
const pi = 3.14159;
```

Une constante ne peut pas être réassignée.

## Types de valeurs

Le runtime de Kastel manipule dynamiquement différents types de valeurs, notamment :

```text
null
boolean
integer
float
string
array
function
object
module
```

L'architecture du runtime permet d'étendre progressivement ces types.

## Conditions

```kastel
let age = 20;

if (age >= 18) {
    print("Adult");
} else {
    print("Minor");
}
```

## Boucles

```kastel
let i = 0;

while (i < 10) {
    print(i);
    i = i + 1;
}
```

## Fonctions

```kastel
fn add(a, b) {
    return a + b;
}

let result = add(10, 20);

print(result);
```

Les fonctions sont des valeurs manipulables par le runtime.

## Tableaux

```kastel
let numbers = [10, 20, 30];

numbers.push(40);

print(numbers[0]);
```

Les tableaux peuvent être modifiés dynamiquement.

Exemple :

```kastel
let values = [];

values.push(10);
values.push(20);
values.push(30);

print(values);
```

## Modules

Kastel possède une architecture permettant d'organiser le code en modules.

Un module peut exposer certaines valeurs :

```kastel
export const answer = 42;

export fn add(a, b) {
    return a + b;
}
```

L'objectif est de permettre ensuite une organisation complète des programmes Kastel autour de modules réutilisables.

# Bytecode

Le code Kastel n'est pas directement exécuté par le système d'exploitation.

Il est d'abord compilé en bytecode.

Exemple conceptuel :

```kastel
let a = 10;
let b = 20;

let result = a + b;
```

peut être transformé en une séquence d'instructions conceptuellement similaire à :

```text
CONSTANT 10
STORE_LOCAL a

CONSTANT 20
STORE_LOCAL b

LOAD_LOCAL a
LOAD_LOCAL b
ADD

STORE_LOCAL result
```

La représentation exacte dépend du format interne du bytecode Kastel.

## Pool de constantes

Les valeurs constantes sont centralisées dans un **constant pool**.

Par exemple :

```text
Constant Pool

0 → 10
1 → 20
2 → "Hello"
3 → "Kastel"
```

Les instructions peuvent ensuite référencer les constantes par leur index plutôt que de stocker directement chaque valeur.

Cela permet de réduire la duplication et fournit une base propre pour l'organisation du bytecode.

## Instructions

Le bytecode est composé d'opcodes représentant les opérations exécutables par la VM.

Exemples conceptuels :

```text
CONSTANT
LOAD_LOCAL
STORE_LOCAL
LOAD_GLOBAL
STORE_GLOBAL

ADD
SUB
MUL
DIV

COMPARE_EQ
COMPARE_LT
COMPARE_GT

JUMP
JUMP_IF_FALSE

CALL
RETURN

ARRAY
INDEX
SET_INDEX

POP
DUP
HALT
```

La liste exacte des instructions évolue avec le développement du runtime.

# Machine virtuelle

La machine virtuelle de Kastel est chargée d'exécuter le bytecode.

Son fonctionnement peut être résumé ainsi :

```text
┌───────────────┐
│   Bytecode    │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ Instruction   │
│    Pointer    │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│   Fetch       │
│   Decode      │
│   Execute     │
└───────┬───────┘
        │
        ▼
┌───────────────┐
│ Stack / Frame  │
│     / VM       │
└───────────────┘
```

La VM suit le principe classique :

```text
Fetch
  ↓
Decode
  ↓
Execute
  ↓
Fetch
  ↓
...
```

## Machine virtuelle à pile

Kastel utilise une architecture d'exécution basée sur une **pile d'opérandes**.

Pour :

```kastel
let result = 10 + 20;
```

la VM peut effectuer conceptuellement :

```text
PUSH 10
PUSH 20

ADD

POP result
```

Avant `ADD` :

```text
┌──────┐
│  20  │ ← top
├──────┤
│  10  │
└──────┘
```

Après `ADD` :

```text
┌──────┐
│  30  │ ← top
└──────┘
```

Cette architecture simplifie notamment la génération du bytecode et l'implémentation des opérations.

# Frames d'appel

Les appels de fonctions nécessitent un contexte d'exécution indépendant.

Kastel utilise des frames pour représenter les appels de fonctions.

Conceptuellement :

```text
VM
│
├── Frame: main()
│
│   └── Frame: add()
│
│       ├── locals
│       ├── instruction pointer
│       └── operand stack
│
└── ...
```

Une frame peut notamment contenir :

* le pointeur d'instruction ;
* les variables locales ;
* les informations nécessaires au retour ;
* le contexte d'exécution de la fonction.

Cela permet à la VM de gérer correctement les appels imbriqués et la récursion.

# Valeurs dynamiques

Le typage dynamique est géré au niveau du runtime.

Une valeur Kastel possède donc une représentation permettant à la VM de connaître son type pendant l'exécution.

Conceptuellement :

```text
Value
 ├── Null
 ├── Boolean
 ├── Integer
 ├── Float
 ├── String
 ├── Array
 ├── Function
 ├── Object
 └── Module
```

La VM peut ensuite effectuer les vérifications nécessaires lors des opérations.

Par exemple :

```kastel
let a = 10;
let b = 20;

print(a + b);
```

La VM reconnaît deux valeurs numériques et peut effectuer l'addition.

# Gestion des erreurs

Kastel distingue les différentes phases pouvant produire une erreur :

```text
Source
  │
  ├── Lexer Error
  │
  ├── Parser Error
  │
  ├── Compile Error
  │
  └── Runtime Error
```

Exemples :

```text
Lexer Error
Parser Error
Compile Error
Runtime Error
Invalid member access
Undefined variable
Wrong argument count
Invalid operation
```

L'objectif est de fournir des erreurs précises permettant d'identifier la phase et la cause du problème.

# Exemple complet

Un programme Kastel peut combiner plusieurs fonctionnalités :

```kastel
const name = "Kastel";

fn sum(values) {
    let result = 0;

    let i = 0;

    while (i < values.length) {
        result = result + values[i];
        i = i + 1;
    }

    return result;
}

let numbers = [10, 20, 30, 40];

let total = sum(numbers);

print(name);
print(total);
```

La chaîne d'exécution est alors :

```text
Programme Kastel
       │
       ▼
     Lexer
       │
       ▼
     Parser
       │
       ▼
      AST
       │
       ▼
   Compiler
       │
       ▼
   Bytecode
       │
       ▼
      VM
       │
       ▼
    Résultat
```

# Philosophie du projet

Kastel cherche à maintenir une séparation claire entre les différentes responsabilités :

```text
Langage
   │
   ▼
Parser
   │
   ▼
Compiler
   │
   ▼
Bytecode
   │
   ▼
Runtime
   │
   ▼
VM
```

Cette séparation permet de faire évoluer le langage sans rendre la machine virtuelle dépendante de la syntaxe source.

Le langage peut ainsi évoluer tandis que le bytecode et le runtime conservent une interface d'exécution stable.
